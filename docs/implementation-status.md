# Implementation status

Version 0.3.0 extends the Windows game-test build with observed team/build tracking and contextual item guidance. All eight sub-agents contributed source research, cached definitions/assets, native acquisition, parsing, state coordination, scoring, interface work and independent verification. The earlier stuck-reading repair remains in place. The user's explicit screenshot/OCR authorization supersedes the archived no-image constraint.

## Working game-test path

- Ordinary Electron starts in Live with automatic screen reading. Provider credentials are not required for this path.
- A self-contained .NET Windows helper checks the real foreground `deadlock.exe` window, validates visibility, captures only the chosen client area, and runs installed Windows OCR. It uses no process-memory access, injection, hooks, or gameplay input.
- The reader is isolated from the interface, at below-normal priority, restricted to one logical CPU. The coordinator allows one request at a time, at most two draft reads per second, no queue, and bounded recovery with confirmed process termination.
- A conservative parser recognizes actual draft cues and the staggered left/middle/right cards. It matches current item names and cached bonus icons, retains unread details as unknowns, and requires two fresh readings with consistent main-card identities before displaying a draft. Confidence drift and missing optional counters do not restart confirmation; changed special details withdraw the preferred pick.
- Small upper/lower HUD regions alternate outside drafts at a total maximum of one scan per second. A positive expanded-scoreboard cue hands off to a wider read; draft context refresh replaces a card read rather than adding another queued request. Native image matching has a 60 ms work budget with own-HUD priority and rotating inventory traversal. OCR rotation and crop-edge bounds remain mapped to the client.
- Picks, changed offers, rerolls, closed drafts, expired readings, and visibility loss clear previous guidance. Unfinished confirmation expires independently of the polling loop. Increasing publication revisions prevent late RPC responses from restoring older cards. Uncertain details still allow clearly limited base-item comparisons, with no firm preference.
- The main Live interface emphasizes the proposed item and its left/middle/right card, plus opposing heroes and observed item icons. Reasons, own/allied builds, abilities, reroll details and reading controls stay behind closed details. All calculations continue while those panels are closed. Pause and automatic-pause retry remain directly available. Demo remains visibly synthetic and separate.
- Context records distinguish positive, unknown, hidden and empty results, with original capture times, source epochs, window sessions and per-field confidence. The reducer merges partial views conservatively, handles proven empty/replacement snapshots, and retires context at observed boundaries. The production detector currently supplies partial inventory views; it does not certify a complete owned grid or read all item variants.
- Local ownership uses a unique full active-Steam display-name row plus independent hero-HUD evidence, or a positively recognized participant control. Display names are read locally at startup; account identifiers and credentials are not passed to the reader or renderer. Spectating/deathcam observations withdraw personal guidance. Ownership expires after 30 seconds unless newly proved; fresh items cannot extend old identity proof. Showing Tab again refreshes observed teams/builds.
- The comparison uses current identified items, source hero/weapon/ability mechanics, observed ability investment, allies and opponents. Identical offers can yield different results after actual context changes. **Base item to consider** compares only main-item base effects across all three cards; unread bonuses/modifiers remain excluded consistently. Unsupported owned-repeat upgrade or stacking semantics withhold both firm and conditional preference.
- A separate ability advisor uses actually observed rank/unlock state and the next source tier. An upgrade-now label additionally requires fresh own AP and a price attached to that tier; older or missing legality gives a conditional priority. A decrease in AP invalidates old rank snapshots until confirmed again.
- Definitions cover 39 heroes, 156 signature abilities and 173 items for client 6745/revision 11078118. Bundled assets include 173 item icons and 278 context images (117 portraits, 156 ability icons and five exact installed HUD glyphs). Build-time hash/source checks run offline; gameplay downloads no models or recognition assets.
- The unsigned Windows directory includes the verified native executable and complete icon cache. `Start Companion.cmd` opens it.

## Evidence and limits

Automated checks cover the real installed Windows OCR engine using authored in-memory fixtures, the production parser/comparison, mocked coordinator transitions, the original store/provider contracts, and actual Electron main/preload/renderer layout. The companion's own layout checks cover 720×1280 and 360×800, maximum text size, expanded controls, partial cards, and automatic pause. Fixture screenshots are clearly marked as development fixtures.

The native OCR fixture identifies Active Reload, Bullet Lifesteal, and Spirit Resilience in the correct positions across whole-window, default, and custom crops. During the user's requested review, four actual combat frames correctly produced no offers. A subsequent draft revealed Toxic Bullets, Tesla Bullets, and Spiritual Overflow; the Windows engine corrected the last name from a small OCR error. The old build's confirmation churn was independently reproduced using changing confidence values, and the revised automatic loop passes a sanitized draft-to-combat replay including missing reroll labels and ten simulated minutes of combat. This establishes a concrete regression repair; it does not establish an overall accuracy rate. See [verification](verification.md) and [performance measurements](performance.md).

The new team, inventory and ability reader is implemented and tested with source-layout/native and contract fixtures; its accuracy on this user's actual scoreboard has not been certified. The user left the match before that check could run. Complete grid semantics, animated bonus/special-modifier coverage, sustained active-reading resources and game frame times remain unmeasured. Fully understood current-card guidance is generally withheld by the conservative reader; the visible conditional main-item comparison remains a heuristic. Exact reroll draw/replacement semantics are unverified, so no probability or reroll-now directive is invented. See [full-context acceptance](full-context-acceptance.md).

The legacy documented-provider adapter, immutable match store, and synthetic scorer remain implemented separately. The original [provider/full-tracking proof](automatic-telemetry-proof.md) is still open: the published feed lacks required own-offer, ownership, ability, reroll, and origin-clock contracts. The original catalogue's `liveModelValidated` flag stays false; the synthetic scorer still refuses Live. The image route uses its separate explicit, limited comparison and does not claim that proof has passed.

Only preferences are saved automatically by the application. Game images, OCR text, offers, and participant state remain in memory. Explicit diagnostics exports contain allowlisted operational aggregates without game images, item choices, or player identifiers. The separately authorized development review saved a small bounded set of local game captures under ignored `optimization/captures`; those private files are excluded from the package and public evidence. Public regression fixtures retain only relevant card names and anonymous draft geometry.
