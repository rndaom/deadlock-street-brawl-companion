# Static bonus-icon cache

This folder contains the 173 public item PNGs for catalog client `6745`, revision `11078118`. They were downloaded at build time from the single approved public Deadlock API asset origin. `manifest.json` pins the catalog SHA-256, every image SHA-256, dimensions, URL, and byte count. It contains no game capture or player data. The native reader does not fetch images during gameplay.

Run `node scripts/sync-reader-icons.mjs --verify` from the project root for an offline integrity check. An explicit `--refresh` rebuilds the cache after a deliberate catalog change. The default command verifies an existing matching cache without making network requests.

The native `IconMatcher` reads this cache once when needed, normalizes RGB and luminance on 8x8/16x16 grids, and searches narrowly around OCR `Bonus!` anchors. It follows the pinned Panorama layout: bonus slot 0 is a 100x100 icon rotated -20 degrees, slot 1 is 80x80 upright. Border pixels and the enhancement-arrow corner are excluded. It requires both a strong template match and a margin over the next distinct item. Returned confidence is template similarity, not a calibrated probability. The explicit role is `bonus`, slots are zero based, and bounds are normalized to the full game client even when the input bitmap is cropped. Every marker emits both inferred slots; an unresolved slot has an empty item ID and confidence zero. The static missing-cache fallback emits the same unknown candidates. A blank slot does not establish that the game offers only one bonus.

The placement comes from the mirrored [draft option layout](https://github.com/SteamTracking/GameTracking-Deadlock/blob/4c6431ccdb816d2911bbbaa4335169cc34140386/game/citadel/pak01_dir/panorama/layout/citadel_item_draft_option.xml) and [styles](https://github.com/SteamTracking/GameTracking-Deadlock/blob/4c6431ccdb816d2911bbbaa4335169cc34140386/game/citadel/pak01_dir/panorama/styles/citadel_item_draft_option.css). The game's bonus images have no item-name label, which is why text recognition alone cannot identify them.

`fixture-proof.json` records an isolated CPU test using generated public-image compositions at the CSS positions, rotations, overlaps, and two scales. It identified 295 of 346 visible synthetic icons, withheld 51 ambiguous cases, and returned no wrong identities. Blank panels produced no item identities and full-client bounds remained correct after cropping. Focused coverage checks verified a known first icon with an explicit unknown second slot, two unknown candidates for a blank marker or missing cache, no candidates without a marker, bounded edge coordinates, and safe malformed-manifest rejection. This is not participant validation and does not measure actual game, hover animation, HDR, or enhancement-overlay accuracy. Missing icon results must preserve unknown bonus coverage; icon identity never establishes modifier bits or complete bundle contents.
