Decision table
1. throughput_low_latency
Decision: Include r_low_latency 0 (Off) as a pure-throughput A/B candidate against 1 (On). Retain On for input-latency preference until measurements establish the tradeoff.
Purpose: Input latency versus actual rendered FPS
Evidence confidence: High confidence in the mechanism; local throughput effect unmeasured
Validation: Use the same warmed scene and consistent uncapped state. Validate the observed cap and AL2 activity separately, then capture throughput with the AL2 overlay off. Compare repeated mean and P95/P99 frame times; report latency separately.
Limit: Off is not guaranteed faster and does not improve image quality. On may reduce latency without a material FPS difference, especially when GPU bound.
Sources: amd-al2-integration, khronos-al-limit, pcgamer-al2-test

2. spatial_equal_scale
Decision: Prioritize equal-scale None/Stretch versus FSR1 at 0.70 and 0.60. Use 0.80 as a clarity control and 0.50/0.40 as optional throughput-ceiling probes.
Purpose: Actual rendered FPS versus edge clarity
Evidence confidence: Native choices confirmed; whole-pipeline winner unmeasured
Validation: Hold the backend and internal pixel count constant, then inspect moving targets and souls. Measure the reconstruction overhead rather than converting pixel reduction directly into an FPS claim.
Limit: Stretch may blur or shimmer. FSR1 may improve edges while costing more GPU work. Scale 0.40 is the native menu minimum, not the standard FSR1 Performance preset.
Sources: amd-fsr1-manual, amd-fsr2, pcgw

3. temporal_tradeoff
Decision: Keep FSR2/FSR3 Quality and Native AA as separate quality and motion-stability candidates. Do not assume that disabling FXAA removes temporal AA.
Purpose: Actual rendered FPS versus motion quality
Evidence confidence: Algorithms documented; current backend gating unverified
Validation: Compare native Quality scale 0.666667 against the same-scale spatial option when available. Test Native AA at 1.0 separately and record the available UI and active backend.
Limit: FSR2/FSR3 integrate anti-aliasing into reconstruction. Temporal history, reactive masks and transparency handling can change ghosting and moving-target readability.
Sources: amd-fsr2, amd-fsr3, pcgw

4. sharpness_claim
Decision: Treat sharpening as an image preference. Do not call FSR1 sharpness 0 'RCAS disabled' or an established FPS gain.
Purpose: Image clarity and evidence accuracy
Evidence confidence: High confidence that the slider-to-pass mapping is unproven

Limit: The SDK exposes a separate enableSharpening control, and historical sharpness conventions differ. A numeric sharpness value alone is not a general pass-disable contract.

Measurement constraints
1. Keep driver, display topology, power plan, clocks, overlays and capture states fixed during config A/B.
2. Warm shaders separately for each native backend; do not reset caches between captures.
3. Use non-mod ETW tooling to measure CPU/GPU/display frame times. Overall CPU utilization alone cannot diagnose a bottleneck.
4. The native AL2 monitor validates activity but does not measure click-to-photon latency; disable its overlay for clean throughput captures.
5. No controlled public benchmark of this current Deadlock build on RX 7800 XT/9800X3D was found that can replace local repeated measurements.
6. PCGamingWiki was checked as a secondary lead. Full-page open failed, but indexed text was available; runtime/performance statements still need direct validation.
7. Default platform-clock guidance does not authorize timer/BCD tweaks. Cold-start profiling, if needed, must be separately labeled rather than mixed into sustained throughput comparisons.

Rejected shortcuts
- Force NVIDIA-only Boost mode 2 on AMD
- Stack RSR with in-game FSR
- Count frame generation as an actual-rendered-FPS gain
- Claim sharpness 0 disables the RCAS pass
- Assume Vulkan is always faster on AMD
- Choose -threads 16 solely from the logical processor count
- Exclude CPU 0, force hard affinity or disable SMT without measurements
- Use historical CS2 Vulkan driver notes as Deadlock's API contract
- Install an older chipset package merely because its notes mention Windows 25H2
- Promise a universal 3 to 8 percent FPS increase from Ultimate Performance
- Delete all VPKs or driver shader caches as an FPS optimization
- Claim RX 7000 hardware can never support FSR4
- Force HPET/platform-clock/timer settings as a general FPS boost
