IR2-01 — P1: compatibility normalization is not established as performance-neutral
Evidence: LEGACY_VIDEO_KEYS removes 31 unique names (32 original occurrences). Twenty corresponding unprefixed names exist in the current convar dump. Several defaults differ from the original stored values: lb_enable_shadow_casting true versus false; r_citadel_distancefield_shadows true versus false; r_distancefield_enable true versus false; r_particle_max_detail_level 3 versus 0; cl_particle_fallback_base/multiplier 0 versus 5. Native storage aliases can differ from console setters, so flags and preset absence alone do not establish whether any old value was effective.
Risk: if an old alias still affects rendering, cleanup can restore shadow/distance-field/particle work and offset the upscaler gain. Conversely, the old zero fog dimensions are below declared minima (width/height 64, depth 48), and r_shadows is cheat/gameinfo_cannot_override; blind reinstatement is not justified.
Action: isolate original reference settings (with equal effective gameplay cap) versus compatibility-normalized FSR2, keeping original scale 0.79999995, AA0, mip2, sharpness0, and other native values unchanged. Document original settings as an experimental reference, not recommended supported setters. Only ordinary, accepted current-build controls should graduate into the delivered performance config; no unhider, unlock or gameinfo override.

IR2-02 — P1: present candidate comparisons confound algorithm, scale and sharpening
The reviewed four profiles use FSR1 80%, native 100%, and FSR2/FSR3 66.6667%. They can answer which bundle wins, but not how much an upscaler alone costs. FSR2 Quality is ~44.4% of output pixels; 80% is 64%, about 44% more internal pixels. The original FSR2 and RCAS stored sharpness values were both 0. The aggressive profile changes only RCAS to 0.2; a temporal challenger that changes FSR2 sharpness to 0.2 introduces another stored difference.
Action: build equal-scale algorithm challengers (FSR1/Stretch at 80%; FSR1/FSR2/FSR3/Stretch at the menu's 66.6667% ratio) and an independent render-scale sweep. Set both inactive/active sharpening storage controls to declared common values in the comparison family to make patched outputs deterministic. Equal numbers do not establish equal visible sharpness across algorithms. Retain a separate original-sharpness normalization control. Treat FSR2/FSR3 80% as custom preserved-baseline experiments requiring live readback, since the temporal ratio enum documents 1/.666667/.588235/.5 rather than .8.

IR2-03 — P2: “20% RCAS sharpening” overstates the known control semantics
The current Valve UI uses a 0–1 slider displayed as a percentage. AMD's original low-level FSR1 RCAS parameter uses stops; 0 is the sharpest and every additional stop reduces sharpening. Its historical integration guide recommends 0.2. The modern FfxFsr1DispatchDescription API instead documents normalized 0–1 sharpness (0 no additional sharpness, 1 maximum) plus a separate enableSharpening flag. Valve's API/version and transformation are not established by the saved UI metadata. Describe the stored/menu control as 0.2, or 20% on the UI slider, rather than a known 20% algorithmic strength. Do not infer that a zero control skips the RCAS pass. This modern-API distinction refines the initial original-stops observation.
Primary sources: https://gpuopen.com/manuals/fidelityfx_sdk/techniques/super-resolution-spatial/ ; https://raw.githubusercontent.com/GPUOpen-Effects/FidelityFX-FSR/master/docs/FidelityFX-FSR-Overview-Integration.pdf ; https://gpuopen.com/manuals/fidelityfx_sdk/reference_documentation/structs/ffx_fsr1_dispatch_description/

IR2-04 — P2: FSR1 with AA off needs a moving-scene clarity control
AMD documents FSR1 after anti-aliased rendering. The Valve menu offers FXAA1 as a postprocess when FSR2 is disabled and describes its cost as small/consistent. The existing FSR1 AA0 candidate is valid as a FPS-first experiment, but spatial reconstruction does not repair all temporal shimmer or thin-target aliasing.
Action: compare FSR1 80% AA0 against exactly the same profile with AA1, and inspect normal-speed distant targets, souls, movement and effect-heavy combat. Do not select on still screenshots or menu/lobby averages alone. The same scrutiny applies to a FSR1 66.7% FPS-first challenger.
Primary AMD source: https://gpuopen.com/manuals/fidelityfx_sdk/techniques/super-resolution-spatial/ ; native Valve UI/localization under the pinned mirror listed below.

IR2-05 — P2: inherited hardware tiers warrant discovery, not guessing
The exact original video file stores cpu_level1, mem_level0, gpu_mem_level0 and gpu_level0. Stock moddefaults classifies >=16 GiB RAM as mem_level2, >=9800 megatexels as gpu_mem_level3, and 8–99 cores as cpu_level2. Those shipped buckets differ from the inherited Potato tiers on 9800X3D/32 GiB/RX7800XT16 GiB. They do not document how current subsystems consume these fields or establish that higher tiers improve throughput.
Action: preserve tiers for matched upscaler experiments. Separately obtain fresh normal auto-detected settings in an explicitly backed-up, game-closed experiment and verify actual tier-dependent behavior before proposing a tier change. Do not copy an old GPU MHz/database heuristic as proof of the best modern setting.
