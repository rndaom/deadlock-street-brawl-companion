Backend and sharpness claims
The README and fsr3equal67 correctly require current-backend/effective-selection validation for FSR3. AMD's distributed SDK lists DX12/Vulkan, and pre-update original community reports describe no DX11 FSR3 menu choice; neither proves that Valve cannot port its upscaler or that the new engine's effective runtime behavior is known. The current UI XML enumerates FSR3 without a declarative DX11 condition. No current C++ availability callback or live query was audited. Do not label FSR3 categorically impossible on this build's DX11 backend, or assume the stored mode 3 is effective. FSR3 TAA does not enable frame generation in these profiles.

The current RCAS control 0.2 wording is accurate. AMD's original low-level RCAS uses stops, while modern FfxFsr1DispatchDescription uses normalized 0–1 plus a separate enableSharpening flag. Valve's mapping/API version and any zero-value pass bypass remain unknown. FSR1 does not provide temporal anti-aliasing; the explicit FXAA challenger addresses motion readability without claiming it is universally faster or clearer.

Critical findings and fixes
IR2F-01 [P2, resolved]: choice returns 255 on errors and 0 on Ctrl+C/Break. The earlier launcher treated 255 as choice 4 and could enter Restore without a selected restore action. Root added >4→finish and explicit1→prepare with a default finish. Static dispatch now maps 1/2/3/4 only to prepare/apply/verify/restore and 0/255 to finish. No interactive launcher or restore was executed by this reviewer.
IR2F-02 [P1, resolved]: the earlier analyzer interpreted v2 CPUStartTime as seconds. Pinned PresentMon CommandLine.cpp defaults MilliSeconds, and CsvOutput.cpp emits CPUStartTime in milliseconds for the selected v2 mode. Root's actual foreground smoke exposed this schema mismatch. Analyzer 1.1.1 defaults this column to milliseconds, supports explicit other-producer overrides, and the wrapper records/validates milliseconds. The continuity/coverage checks remain intact rather than guessing a unit from numeric magnitude.
IR2F-03 [P1, resolved]: unknown/incomplete ETW loss counters previously warned but could qualify for comparison. Both report eligibility and compare admission now require known-zero loss status. CSV negative/fractional counters also reject. The actual source's final overflow warning is parsed so a final nonzero warning overrides an earlier zero status.
IR2F-04 [P2, resolved]: permitted 30–59-second analysis windows previously printed a command with the analyzer's default 60-second minimum. The wrapper now prints an explicit minimum min(declared analysis duration, 60), retaining the 30-second authoring floor and existing coverage/hitch checks. This enables exploratory screening; it does not turn one short observation into profile proof.
IR2F-05 [P2, resolved]: the collector wait could hang indefinitely. The wrapper now uses bounded waits and a deadline delay + duration + 30 seconds. It only terminates its returned collector after matching PID, process creation time and pinned executable; it records incomplete status. It does not stop the game, process trees or unrelated ETW sessions.
IR2F-06 [P1, resolved]: analyzer 1.2.0 requires known machine/build/driver/scenario/backend/camera/background text, positive numeric output width/height/refresh, and a nonnegative numeric fpsMaxRuntime (0 explicitly permitted). Replay context requires a SHA256 or known replay ID, nonnegative integer start/end ticks with end > start, and positive playback speed. A native-scene alternative requires a map, reproducible procedure and state ID. Empty, unknown and angle-bracket template values remain analyzable observations but cannot enter verified comparisons. The comparator independently revalidates concrete context, so preexisting or hand-edited eligibility flags cannot bypass the gate; all context must also match exactly. Native-scene conclusions use consistentScenarioImprovement and do not claim a replay improvement. This is structural declaration validation, not automatic proof of physical readback or reproduced camera/scene/background conditions.
